# 历史会话、恢复与每轮总结

2026-09-05。主交互终端使用原生滚动历史，不切全屏。

- 每次启动／重启 `loop` 都新建 Session，历史、草稿、附件、队列和累计用量不自动载入；原会话完整保留，用 `/resume` 显式恢复。
- `/resume`：显示当前提供商/模型的已保存会话列表，并打开输入栏的历史会话补全菜单。方向键/Tab 按标题选择，Enter 直接恢复选中会话；光标位于 `/resume ` 末尾。成功后显示会话标题，直接输入即可沿用该会话上下文继续对话。
- `/history [TITLE]`：查看当前或指定会话的完整已保存消息和逐轮总结。
- `/resume TITLE`：恢复该会话消息、总结、草稿与附件，并清除当前终端画面和旧滚动记录，在输入框上方重画目标会话的完整已保存消息。恢复的旧队列保持暂停；当前有运行任务、待发队列或附件时不会悄悄切走。失败时保留原会话和画面。
- `/new`：开始独立会话，同时将上方聊天显示清空，原会话仍保存于数据库。若还有队列/附件先处理它们。
- `/rename NAME`：命名当前会话，支持空格，限制 100 个可显示字符。名称独立持久化，不进入模型消息，后续保存/重开仍保留。
- `/sessions [QUERY]`：按名称、ID 或消息内容搜索当前提供商/模型的历史；先检索全部记录，再显示最多 30 个结果。空参数列最近会话。
- `/resume 关键词` 的候选可按 ID 或标题筛选；选中候选后提交可读标题（重名附稳定序号），内部解析回对应记录。跨提供商/模型的记录不会混入列表。
- `/export [TITLE]`：导出当前或指定会话的消息、工具调用和逐轮总结到 state-dir/exports 下的独立 Markdown 文件。不覆盖已有导出；不导出 provider 配置、未发送草稿、附件的内嵌媒体内容。对话文字与工具文本按实际记录导出，不保证对话中用户自行写入的敏感内容会自动脱敏。以上三项管理命令仅交互终端可用，执行中须先等待当前回合结束。
- `/queue resume`：仅继续排队任务。原 `/resume` 的队列功能迁到此处，浏览历史不会执行任务。

`conversation.sqlite` 新增 sessions 表，不覆盖旧 transcript/checkpoint。只有 checkpoint 的旧记录在打开会话库时先归档为可选择会话；过去已被旧代码裁掉、没有另行存档的历史无法凭总结还原。会话列表按 endpoint/model/protocol 隔离，不把其他提供商的上下文自动送给当前模型。没有新增全局数据库或模型服务。

每次 ChatAgent.reply 无论成功、工具失败、取消还是网络异常，都生成确定性总结，保存请求、答复摘要、工具证据及错误状态。答复摘要明确不是执行证据；只记录实际 result 事件里的场景路径/加载哈希/物品/执行回执等，不让模型自己写一个“成功哈希”充当证据。默认不在每轮对话后显示 `Summary`，可通过 `/history` 或历史会话预览查看已保存的总结。无需额外模型请求。摘要不是另一轮推理，长篇技术答复仍应查完整历史。

完整会话保存在本地，不再因上下文裁剪而删除旧消息。送模型的正文按完整对话组最多取最近 32 条消息，按原有媒体计量方式限制 12000 字符等价预算；另注入最近 12 轮的请求和工具证据，预算上限 16000 字符。旧答复摘要不放进这份工具证据记录。当前上下文仅自动提供工作目录、已加载工具组和对应权限；窗口、设备与任务状态须通过工具按需查询，当前工具回执优先于旧对话陈述。这里限制的是历史段，不是整个请求的总 token 上限；工具 schema 和实时状态另计。

## 对模型失误的判断

已证实的工程原因是漏路由、独立场景语义缺失、旧 Python 进程不热更新，以及保存历史时错误复用裁剪结果。旧对话包含虚假的“不支持”和成功证据，会造成干扰风险；没有做同模型/同任务/不同上下文的对照实验，不能断言“模型性能差”或“上下文过长”是主因。新规则减少这类干扰，但不等于模型不会再出错。

验证入口：test_session_resume（完整历史、预算、隔离、失败总结、历史补全）、test_interactive（选择会话不运行队列）、test_session_render（真实 PTY 中文流式期间编辑草稿、总结、历史选择菜单）。实际 MuJoCo 仍由原有 worker 管理，恢复聊天不自动回滚其场景文件。

## 2026-09-07：无损上下文视图

`/context` 展示完整历史数量、实际选择数量、遗漏数量及字符预算（不是 token 用量，不含系统提示/schema/当前回合）。默认窗口最多32条、12000字符等价预算，媒体每项计2000；按用户/助手完整组选择，执行中追加的多个用户输入不拆散。较早用户请求保留首条与最近六条的有限摘录，合计不超过2000字符；明确标注历史数据与未验证边界，不把旧助手文字变成执行证据。这是确定性摘录，不是模型生成摘要。

`/compact` 将当前进程的模型历史窗口缩为最多8条，保留历史摘录与完整持久历史；`/compact reset` 恢复32条默认。窗口偏好现在随会话持久化（详见下节Token预算）；不发起额外模型请求。`/history`、导出与恢复不因压缩丢失原文。

单个工具返回超过12000字符时使用可解析 JSON 摘录并显式标记 truncated，完整回执仍经原事件记录通道保存。长工具循环累计工具正文超过48000字符时优先缩短较旧结果，保留 assistant tool_calls 与 tool_call_id 配对；模型须分页重新读取所需细节。以上预算不等于整个模型请求的 token 上限。

## 2026-09-07：Token 计量与自动窗口预算（取代上文固定窗口说明）

输入框下方显示 `Session Tokens 累计值 | Context 使用量/容量 百分比`。显示值是本次启动内、当前前台 Session 新增的 input+output usage，包括同一轮工具循环中的多次请求；每次重开 `loop` 从 0 显示。启动后首次 `/resume` 某个历史 Session 也从 0 显示，同次启动切走再回来保留该 Session 本次累计；`/new` 开始独立统计。以首次载入的历史计数作为内存基线，历史累计 usage 仍正常保存，`/context` 的 token_usage 保留历史累计口径。不包含独立子 Agent、后台 Task、连接探测或其他客户端的调用，不是账号账单。缺失 usage 的请求单独计数并显示 `+`，不能当成消耗为零。旧会话没有 usage 时无法追溯补算。

`Context` 请求前使用带 `~` 的估算，收到 usage 后显示最近一次请求的 input+output；这与整个历史累计量不同。`/context` 展示最近实际输入 token、请求估算、输出预留、触发阈值、历史条数和累计/缺报次数。估算覆盖编码后的系统提示、工具定义、历史和当前轮工具回执：文本按 UTF-8 字节保守估算，图片使用配置预算，未引入 tokenizer 依赖。该估算不保证等于供应商计数；容量或请求用量未知显示 `?`。

当前 provider profile 支持以下可选字段，通过既有 `/config profiles` 读取，再用 `/config set profiles` 的 `operation:save`、完整 `config`、`replace:true` 保存，沿用现有配置权限流程：

| 字段 | 含义 |
| --- | --- |
| `context_window` | 供应商确认的当前模型总窗口 token 容量，正整数；未配置时不猜模型容量 |
| `max_output_tokens` | 单次输出上限/预留，默认4096；同时用于 Chat Completions 与 Responses 请求 |
| `compact_threshold` | 扣除输出预留后的自动压缩比例，默认0.8，范围0.1–0.95 |
| `image_token_budget` | 每幅图的估算预算，默认8192；需按服务商和实际图片规格调整 |
| `stream_usage` | Chat Completions 请求 `stream_options.include_usage`，默认true；不支持此字段的服务商可显式设false，缺报仍标记 |

例如供应商确认窗口为128000时，可在既有 profile 中增加 `"context_window":128000,"max_output_tokens":4096,"compact_threshold":0.8`，不要把示例容量直接当成任何模型的规格。切换完整 profile 采用新配置；只用 `/model ID` 更换模型会清除旧模型的容量，避免误用。

配置容量后，近期历史先按容量选择，再在**每次模型请求前**检查整个请求的预算；较早对话组及旧工具调用/回执整组转为明确标记的不完整摘录。保留本轮原始输入、后续纠正、系统及实时任务状态、最近一组工具调用。历史裁剪后补入已有逐轮请求与实际工具记录；原始历史和事件保持可查询，助手旧答复不能变成执行证据。无额外模型摘要请求，也不会为了压缩重执行工具。这是有损的确定性整理，不宣称模型能逐字记住全部内容。

未配置容量时沿用12000字符/32消息历史视图，并按系统/工具/当前输入成本加本地余量整理工具循环，**不把本地余量当成模型硬上限**。`/compact` 为下一次请求选择最多8条近期历史并保留摘录/逐轮记录；`/compact reset` 回到自动默认。该偏好、usage和最近预算报告随会话保存。配置容量且当前不可裁剪部分仍超预算时，保留已有历史并报告具体减载方向，不发送已知超预算请求。网络故障、服务商限制和未准确配置的视觉容量仍可能中断请求，不能保证永不中断。

验证：`test_token_budget`、`test_stream_completion`、`test_context_window`、`test_session_resume`；`test_slash_terminal` 的真实PTY检查用量栏及中文流式期间输入草稿。未调用付费模型或机器人。

### 重复读取与压缩回执修正（2026-09-07）

完整历史/工具事件保存和模型当前可见上下文是两层。旧回执 ID 可能仍在当前 messages 中，但其正文已经被压缩；仅检查 ID 会生成没有完整正文可用的复用引用。本次改为比对原回执正文、sha256、分页和相关字段，正文不在时重新提供缓存中的完整回执。文件变化仍按哈希失效，不将过期内容复用。

未变化的缓存读取不作为续接进展。重复读取/检查连续两轮无新证据时给模型一次换方法提示；连续六轮仍无新证据则工具禁用收尾，明确标记 repeated_without_new_evidence，不把它说成硬件故障。此规则针对重复检查，不是重新引入前台固定轮次上限；普通执行调用及动态状态工具不套用只读空转收束。相同 Python 输出生成的新报告路径也不作为新的检查进展。程序仍不会把“读过回放脚本”变成“已播放”。
