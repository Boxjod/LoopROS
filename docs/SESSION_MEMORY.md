# 历史会话、恢复与每轮总结

2026-09-05。主交互终端使用原生滚动历史，不切全屏。

- `/resume`：显示当前提供商/模型的已保存会话列表，并打开输入栏的历史会话补全菜单。方向键/Tab 按标题选择，Enter 直接恢复选中会话；光标位于 `/resume ` 末尾。成功后显示会话标题，直接输入即可沿用该会话上下文继续对话。
- `/history [TITLE]`：查看当前或指定会话的完整已保存消息和逐轮总结。
- `/resume TITLE`：恢复该会话消息、总结、草稿与附件，并清除当前终端画面和旧滚动记录，在输入框上方重画目标会话的完整已保存消息。恢复的旧队列保持暂停；当前有运行任务、待发队列或附件时不会悄悄切走。失败时保留原会话和画面。
- `/new`：开始独立会话，同时将上方聊天显示清空，原会话仍保存于数据库。若还有队列/附件先处理它们。
- `/rename NAME`：命名当前会话，支持空格，限制 100 个可显示字符。名称独立持久化，不进入模型消息，后续保存/重开仍保留。
- `/sessions [QUERY]`：按名称、ID 或消息内容搜索当前提供商/模型的历史；先检索全部记录，再显示最多 30 个结果。空参数列最近会话。
- `/resume 关键词` 的候选可按 ID 或标题筛选；选中候选后提交可读标题（重名附稳定序号），内部解析回对应记录。跨提供商/模型的记录不会混入列表。
- `/export [TITLE]`：导出当前或指定会话的消息、工具调用和逐轮总结到 state-dir/exports 下的独立 Markdown 文件。不覆盖已有导出；不导出 provider 配置、未发送草稿、附件的内嵌媒体内容。对话文字与工具文本按实际记录导出，不保证对话中用户自行写入的敏感内容会自动脱敏。以上三项管理命令仅交互终端可用，执行中须先等待当前回合结束。
- `/queue resume`：仅继续排队任务。原 `/resume` 的队列功能迁到此处，浏览历史不会执行任务。

`conversation.sqlite` 新增 sessions 表，不覆盖旧 transcript/checkpoint。现有 checkpoint 在首次保存时迁入可选择会话；过去已被旧代码裁掉、没有另行存档的历史无法凭总结还原。会话列表按 endpoint/model/protocol 隔离，不把其他提供商的上下文自动送给当前模型。没有新增全局数据库或模型服务。

每次 ChatAgent.reply 无论成功、工具失败、取消还是网络异常，都生成确定性总结，保存请求、答复摘要、工具证据及错误状态。答复摘要明确不是执行证据；只记录实际 result 事件里的场景路径/加载哈希/物品/执行回执等，不让模型自己写一个“成功哈希”充当证据。默认不在每轮对话后显示 `Summary`，可通过 `/history` 或历史会话预览查看已保存的总结。无需额外模型请求。摘要不是另一轮推理，长篇技术答复仍应查完整历史。

完整会话保存在本地，不再因上下文裁剪而删除旧消息。送模型的正文按完整对话组最多取最近 32 条消息，按原有媒体计量方式限制 12000 字符等价预算；另注入最近 12 轮的请求和工具证据，预算上限 16000 字符。旧答复摘要不放进这份工具证据记录。当前上下文仅自动提供工作目录、已加载工具组和对应权限；窗口、设备与任务状态须通过工具按需查询，当前工具回执优先于旧对话陈述。这里限制的是历史段，不是整个请求的总 token 上限；工具 schema 和实时状态另计。

## 对模型失误的判断

已证实的工程原因是漏路由、独立场景语义缺失、旧 Python 进程不热更新，以及保存历史时错误复用裁剪结果。旧对话包含虚假的“不支持”和成功证据，会造成干扰风险；没有做同模型/同任务/不同上下文的对照实验，不能断言“模型性能差”或“上下文过长”是主因。新规则减少这类干扰，但不等于模型不会再出错。

验证入口：test_session_resume（完整历史、预算、隔离、失败总结、历史补全）、test_interactive（选择会话不运行队列）、test_session_render（真实 PTY 中文流式期间编辑草稿、总结、历史选择菜单）。实际 MuJoCo 仍由原有 worker 管理，恢复聊天不自动回滚其场景文件。

## 产品主线纠偏

2026-09-05 用户明确：核心是 Agent 反馈与循环，MuJoCo只是一个执行工具。每次成功修改 MuJoCo 场景状态后自动重启并核对加载状态；其他修改不触发重启。会话恢复和每轮总结提供上下文与记录，不等于目标验收、失败修正和再执行已闭环。现有 core/loop.py 有特定模拟本体的 execute→observe→review 循环；terminal/llm.py 是有界工具调用循环，模型依据工具结果继续处理并作答，已移除领域固定答案替换，两者不能宣称已覆盖所有机器人任务。后续验收应检查实际目标差距、修正行为和终止证据，不以窗口是否打开为中心。

会话列表和历史预览现位于输入区 Actions 面板，PgUp/PgDn 浏览、Esc 关闭；选择候选并按 Enter 恢复，恢复确认也在面板内，目标会话正文直接显示在上方原生滚动区。面板显示记录为 Operator 事件，不进入模型 user/assistant 历史。开始发送普通消息即关闭面板。

历史重画保留用户/助手、推理文字和工具调用摘要，媒体显示占位符；不展开图片编码、Responses 隐藏字段或大段工具 JSON，不伪造工具耗时或 `/details` 事件 ID。重画不重新写入消息/工具事件，不调用模型或工具。终端控制字符按文本处理，粗体与用户背景样式沿用现有显示。清理滚动记录依赖终端支持 CSI 3J（传统 Win32 使用整缓冲区清理）；Linux PTY 已验证，Windows/macOS 实机未测。

## 2026-09-07：无损上下文视图

`/context` 展示完整历史数量、实际选择数量、遗漏数量及字符预算（不是 token 用量，不含系统提示/schema/当前回合）。默认窗口最多32条、12000字符等价预算，媒体每项计2000；按用户/助手完整组选择，执行中追加的多个用户输入不拆散。较早用户请求保留首条与最近六条的有限摘录，合计不超过2000字符；明确标注历史数据与未验证边界，不把旧助手文字变成执行证据。这是确定性摘录，不是模型生成摘要。

`/compact` 将当前进程的模型历史窗口缩为最多8条，保留历史摘录与完整持久历史；`/compact reset` 恢复32条默认。窗口偏好不持久化，重启回到默认；不发起额外模型请求。`/history`、导出与恢复不因压缩丢失原文。

单个工具返回超过12000字符时使用可解析 JSON 摘录并显式标记 truncated，完整回执仍经原事件记录通道保存。长工具循环累计工具正文超过48000字符时优先缩短较旧结果，保留 assistant tool_calls 与 tool_call_id 配对；模型须分页重新读取所需细节。以上预算不等于整个模型请求的 token 上限。
