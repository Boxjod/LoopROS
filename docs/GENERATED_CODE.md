# 生成代码、项目与机器人资料存放规则

2026-09-07。用户使用 Loop 产生的检查、连接、启动、控制、轨迹脚本及操作记录属于用户工作资料，不因“能运行”就成为 Loop ROS 产品源码。

| 类型 | 权威位置 | 是否进入本仓库 Git／发行 |
| --- | --- | --- |
| 标准库契约、任务、资源与持久化运行时 | `core/` | 正式维护源码 |
| 对话、文件工具、权限与执行接入 | `terminal/` | 正式维护源码 |
| 已审核通用设备／仿真实现 | `toolchain/` | 审核、测试后作为正式源码 |
| 安装、构建、发行维护脚本 | `scripts/` | 正式维护源码；不是用户临时脚本目录 |
| 项目辅助代码 | `user_projects/<project>/scripts/` | 仅本地，不暂存、不上传、不发行 |
| 已确认型号的辅助代码 | `user_projects/<project>/robots/<model>/scripts/` | 仅本地，不暂存、不上传、不发行 |
| 项目／型号说明、操作记录与输出 | 对应目录的 `docs/`、`artifacts/` | 仅本地 |
| 可移植用户工具与完整 Skills | `~/.loop/tools/`、`~/.loop/skills/` | 使用既有专用工具接口，不复制回发行目录 |
| 待审核的产品能力候选 | `toolchain/candidates/` | 仅本地；用户明确审核后才可提升 |
| Loop 的会话、工具回执和内部状态 | 现有运行状态目录；源码运行通常是 `artifacts/terminal/` | 不随辅助脚本迁移，不进入源码 |

现有应用项目的源码继续在原结构维护；上述分类针对使用 Loop 时产生的辅助代码，不要求把用户正在开发的应用搬进新目录。根目录仍是 `loop_robot` 包：保留八个包／安装／更新模块，以及 `loop`、`loop-switch`、README、AGENTS 和打包配置。设备脚本不归入 `core`。

## 创建与检索

1. 先读 `user_projects/README.md`，再读目标项目 README；按任务寻找已有脚本与实际回执，避免重复生成检查文件。
2. 复用已有项目名和型号标识，路径片段用简短稳定的名称。型号依据已知项目实现／设备配置；不从 Jetson 主机名、IP 或电机型号猜机器人型号。未知型号放项目级 `scripts/`；未知项目暂放 `user_projects/unclassified/` 并在索引标注待归类，不阻塞普通文件工作。
3. 新辅助代码写入对应 `scripts/`，本地说明写入 `docs/`，输出写入该项目／型号下 `artifacts/`。索引只记录用途、文件入口、必要运行目录、前提、验收状态和证据路径；凭据继续走用户凭据入口，不写入代码／索引。
4. 为保持检索简洁，`search_files` 从工作区根搜索时跳过 `user_projects`；显式指定 `user_projects/<project>` 可搜索该项目。`list_files` 仍显示目录，`read_file`／`python_check`／`run_python` 使用实际新路径。
5. 可复用流程只有已有实际验证才保存为用户工具／执行型 Skill；本地脚本的存在、语法通过和旧回执都不代表当前设备就绪。修改／迁移保持原内容与历史证据，更新实际引用；不为整理重新连接设备或执行动作。

基础模型上下文和 `write_file` schema 提供存放规则，实时上下文包含绝对 `generated_code_root`。默认工作流也包含同一约定。`write_file` 在 Loop ROS 自身包根拒绝新建 Python／Shell／PowerShell／批处理脚本，并给出分类路径；现有包入口编辑和普通用户项目根文件写入保持可用。这是文件工具路径约束，任意宿主脚本仍可自行写文件，不能据此宣称全面文件系统隔离。

## Git 与发行

本仓库 `.gitignore` 排除整个 `user_projects/`，根目录 Python 与 Markdown 使用维护入口白名单。用户目录本地 `.gitignore` 同时排除自身内容。新建其他工作区的用户目录也应先设置忽略规则，不仅依赖模型口头约定。

提交前检查 `git ls-files -ci --exclude-standard` 和 `git ls-files -- user_projects`，两者应为空；发现误暂存时仅移出用户产物并保留文件，不重置其他改动。`tests/test_public_source.py` 对当前暂存索引做此检查。`scripts/build_release.py` 除按 Git 跟踪／忽略规则构建外，独立排除 `user_projects/`，即使目录被强行暂存且遗漏忽略规则，也不会复制到发行源树；wheel 检查也拒绝此目录。此检查不等于安装了 Git hook，提交前仍须运行验证。

用户脚本提升为产品能力，必须有用户明确审核、可复用接口、合适的模块归属及相应测试；移除具体设备路径／私有参数并使用配置入口。不要把全部生成代码搬进 core、scripts 或 examples 后整体上传。
